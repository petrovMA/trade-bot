# ТЗ: Сделать документацию AI-friendly

## Промпт для агента

Скопируй промпт ниже и передай любому AI-агенту (Claude Code, Cursor, Copilot, etc.) вместе с доступом к репозиторию.

---

### Промпт

```
## Задача

Улучши навигацию по документации проекта для AI-агентов.
Цель — агент должен за 0-1 tool call понять: какие доки есть, что актуально, что устарело, и где связь между кодом и документацией.

## Архитектура решения

Документация организована в 3 уровня:

1. **Конфиг агента** (CLAUDE.md / .cursorrules / AGENTS.md) — однострочная ссылка на docs/map.md
2. **docs/map.md** — полная карта: таблица документов со статусами, Code→Docs mapping, дерево папок
3. **Каждый .md файл** — YAML frontmatter + Context-секция

Это разделение позволяет:
- Не раздувать конфиг агента (он загружается в системный промпт каждый раз)
- Масштабироваться до 50+ документов без потери навигации
- Обновлять карту в одном месте

## Что нужно сделать

### 1. Ссылка в конфиг-файле агента

Добавь в файл инструкций агента (CLAUDE.md, .cursorrules, AGENTS.md или аналог):

```markdown
## Documentation
Карта документации, статусы (active/deprecated) и связи code↔docs: **`docs/map.md`**
```

Одна строка. Не таблица, не список — только ссылка. Вся детализация живёт в map.md.

### 2. Создай docs/map.md

Файл содержит 3 секции:

```markdown
---
title: Documentation Map
description: Карта документации проекта — статусы, связи code↔docs, навигация для AI-агентов
tags: [index, navigation, meta]
status: active
---

# Documentation Map

Карта всей документации проекта. AI-агенты: читай этот файл первым для навигации по docs/.

## Документы

| Документ | Статус | Описание |
|----------|--------|----------|
| `path/to/doc1.md` | **active** | Краткое описание — 1 строка |
| `path/to/doc2.md` | **deprecated** | Что это и почему устарело |
| `path/to/doc3.md` | **draft** | В процессе написания |

## Code → Docs

| Код | Документация |
|-----|-------------|
| `SomeClass.kt` (feature X) | `path/to/design-doc.md` |
| Docker/nginx config | `path/to/deployment-guide.md` |

## Структура папок

```
docs/
├── map.md              ← ты здесь
├── index.md
├── architecture/
│   └── ...
├── guides/
│   └── ...
└── reference/
    └── ...
```

## Правила обновления

- При добавлении нового .md — добавь строку в таблицу "Документы"
- При связывании кода с документацией — добавь строку в "Code → Docs"
- При устаревании документа — смени статус на **deprecated** и укажи замену
```

### 3. YAML Frontmatter в каждом .md файле

В начало каждого файла документации добавь:

```yaml
---
title: Название документа
description: 1 предложение — о чём этот файл
tags: [2-4 тега]
status: active | deprecated | draft
related_files: [путь/к/связанному/коду.kt, путь/к/другому/доку.md]
---
```

Поле `status` критично:
- `active` — актуальный документ
- `deprecated` — устаревший, указать что использовать вместо
- `draft` — в процессе написания

### 4. Context-секция в начале каждого документа

Сразу после заголовка H1 добавь секцию `## Context` (2-3 предложения):
- Зачем этот документ существует
- Какую проблему решает
- Если deprecated — что использовать вместо
- Связь с кодом (какие файлы реализуют то, что описано)

Пример:
```markdown
## Context
Дизайн-документ для оптимизации AlgorithmGrid при ценовых спайках.
Код реализации: `spike/SpikeDetector.kt`, `spike/PriceStabilizer.kt`.
```

### 5. Deprecated-баннер для устаревших документов

Для устаревших документов добавь blockquote сразу после заголовка:

```markdown
> **DEPRECATED**: Этот документ описывает [что]. Актуальный подход — см. `path/to/active-doc.md`.
```

### 6. Статусы в index.md (если есть)

Если есть индексный файл документации, добавь статусы к каждой ссылке:

```markdown
- `doc-name.md` — описание. **[active]**
- `old-doc.md` — описание. **[deprecated]** — не используется
```

## Правила

- НЕ меняй содержание документов, только добавляй метаданные
- НЕ удаляй deprecated документы — помечай их
- НЕ дублируй таблицу из map.md в конфиг агента — только ссылка
- Description в frontmatter — максимум 1 предложение
- Context — максимум 3 предложения
- Tags — 2-4 штуки, lowercase, через запятую
- Code→Docs mapping — только реально существующие связи
- Все пути в map.md — относительно docs/ (без префикса docs/)

## Почему именно так

| Техника | Эффект | Причина |
|---------|--------|---------|
| docs/map.md (отдельный файл) | **Высокий** | Масштабируется до 50+ доков, не раздувает конфиг агента |
| Ссылка в конфиге агента | **Высокий** | Агент знает куда идти, 1 tool call до полной карты |
| Status (active/deprecated) | **Высокий** | Агент не тратит время на чтение устаревших доков |
| Context секция | **Средний** | 3 предложения дают суть без чтения всего файла |
| Code→Docs mapping | **Высокий** | Агент знает куда смотреть при изменении кода |
| YAML Frontmatter | **Низкий** | Полезно для tooling, но агенты редко парсят YAML отдельно |

## Антипаттерны (НЕ делай)

- Не вставляй полную таблицу документов в конфиг агента — она разрастётся и засорит системный промпт
- Не пиши длинные description (3+ предложений) — это не Context секция
- Не дублируй содержание документа в Context — только суть и связи
- Не создавай несколько файлов-маппингов — всё в одном map.md
```
